# Текущая приёмка командной VM

Обновлено 22.10.2026. Это состояние развёрнутого CPU-профиля, а не обещание
промышленной готовности. Описание старого браузерного прототипа в карточке
портала не описывает текущий телефонный маршрут.

## Подтверждено испытаниями

- Входящий SIP: шлюз организатора → Asterisk/ARI/AudioSocket → настоящий звук
  и DTMF → Whisper → Rust → GigaChat → CRM → подтверждённый визит DBI.
  Испытание: `debug/run_vm_sip_booking.py`. Тестовый визит затем отменяется.
- Голос, тоны и совместный ввод отдельно: `debug/run_vm_live.py`. Настоящий
  Silero PCM проходит production VAD/детектор; текст вместо ASR не подставляется.
- Передача человеку: `telephony.py` соединяет каналы после ответа софтфона;
  `crm.py` создаёт `/escalations` только после соединения, для проверенного
  пациента. Повтор событий не дублирует POST; потерянный ответ требует сверки.
- Исходящее напоминание: `debug/run_vm_reminder.sh`, только собственный
  тестовый софтфон. До сведений о визите проверяется карта. Подтверждение
  локальное: у DBI нет соответствующего статуса. Контакт восстанавливается.
- Перенос из reminder: настоящий звук → ASR → NLU → Rust → DBI в
  `debug/run_vm_reminder_replay.py`. Это проверка без SIP-дозвона. Первый
  исходящий перенос нашёл ошибку NLU; исправление принято этим воспроизведением.
- После рестарта агент остаётся в режиме настоящего GigaChat-3-Pro; запись DBI
  повторена. Настройки сохраняются, а модель выбирает только разрешённые слоты.
- 770 интеграционных тестов без ошибок и пропусков, повтор на свежих томах
  по `compose.test.yaml`, без сети и секретов во время тестов. Это число тестов,
  а не метрика точности распознавания или результат клинического пилота.
- Nginx и HTTPS сохраняют работоспособность после пересоздания редактора.
- Браузерный WAV-прогон 22.10: шесть реплик через ASR, выбранный талон,
  отдельное подтверждение, настоящий INSERT в изолированную SQLite. Снимок
  экрана сохранён у команды. Физический микрофон этим не проверен.

Обезличенные результаты: [public-summary.json](../../debug/runs/hackathon-final/public-summary.json).
Сырые трассы, XML и аудио хранятся закрыто на VM под `debug/runs/`.
Порядок запуска: [deploy/vm/README.md](../../deploy/vm/README.md).

## Ограничения и следующий пилот

Браузерный пробный звонок использует отдельную SQLite. Телефонный маршрут
использует DBI. Успех в одной картотеке не выдаётся за успех в другой.
Все испытания выполнены с вымышленными карточками и синтетическим голосом.

Доставка SMS, работа живой смены, новая личность голосом, реальные шумы/акценты,
массовая кампания с согласием и производственные SLA остаются вне приёмки.
Массовый обзвон выключен; явный список получателей не отменяет согласие,
рабочие часы, интервалы и суточный бюджет. Секреты, модели и карточки не в Git.

Для пилота нужен один номер и реальный регистратор. По журналу звонков измерять
долю завершённых типовых обращений, пропуски, время ответа и перевода, ошибки
записи и неявки до/после внедрения. Считать знаменатель и период наблюдения;
цели кейса не выдавать за достигнутый эффект. Очередь SMS подключать только
после выдачи шлюза, проверки доставки и согласия получателей.

Медицинская граничная реплика: выбор кнопок озвучен явно («нажмите один», «нажмите два»). Проверка `debug/run_medical_boundary_audio.py` читает фразу из действующего сценария и проверяет настоящий Silero → CPU ASR в PCM, A-law и μ-law. Все три маршрута сохранили числа, WER 0; свежий полный аудиобанк 41/41 прошёл. Это автоматическая акустическая проверка, не оценка естественности живыми слушателями.

Отказ сохранения callback озвучивается явно: «Заявка не сохранена». Проверка `debug/run_medical_boundary_audio.py --callback-failure`: PCM/A-law/μ-law, WER 0, отрицание сохранено. Полный банк после обеих правок прошёл 41/41 локально и через рабочий Whisper. 38 целевых callback/CRM/hours tests прошли; критерии чисел и полярности не ослаблялись.
